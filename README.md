# Taply website

Single-page marketing and sales site for the Taply Versatile Plastic NFC Smart Business Card (KES 5,500).
Built from the Taply Design and Implementation Specification and the Taply Brand Guideline.

**Stack:** React 19, Vite, TypeScript, custom CSS. No animation or UI libraries.

## Run

```bash
npm install
npm run dev      # local dev server
npm run build    # type-check + production build into dist/
npm run preview  # serve the production build
```

### Logo deviation (authorised)

The symbol in `taply-logo.png` and `taply-logo-reversed.png` has been enlarged by 30% so it holds its own
next to the wordmark. This was explicitly authorised by the site owner as an exception to the "never modify
the logo" rule. Only the symbol was scaled (Lanczos) and repositioned: it is vertically centred on the
wordmark's cap height (top of the "T" to the baseline), so it now rises a little above the "T", and the gap
to the wordmark equals the symbol's own bar thickness. Nothing was recoloured, redrawn, skewed or given
effects, and the wordmark pixels are untouched. The canvas grew from 1649×453 to 1794×479 (rows added at the
top only); `BrandMark` and the logo slots (nav, footer, product cards, the "Your card" card) were updated so
the wordmark keeps its size and position.

- Originals: `public/brand/originals/`
- Script: `python scripts/resize-logo-symbol.py [scale]` (always reads from the originals, so scaling never
  compounds; default scale 1.30)
- If official export files arrive, ask the brand owner for a lockup with the larger symbol rather than
  re-running the script on them, since raster upscaling slightly softens the symbol.

## Notes

- Fonts (Manrope, DM Mono) are self-hosted through Fontsource instead of the Google Fonts `@import`; same families and weights.
- Orders go to WhatsApp: every "Get your Taply card" button (nav, mobile menu, hero, pricing, final CTA) and the footer's "Order on WhatsApp" link open a `wa.me` chat with a prefilled message, in a new tab. The number (`WHATSAPP_NUMBER`) and message (`ORDER_MESSAGE`) are set in `src/components/shared.tsx`, which builds `ORDER_URL` from them. The footer keeps a link to `https://taply.com`. No checkout is built.
- The Amara Mensah profile is the sample from the brand guideline, shown as a product demonstration (not a testimonial). It carries no on-page caption; screen readers hear it described as a sample profile.
- Nothing is invented beyond the spec's confirmed facts (no delivery, warranty, payment or dimension details). The only ordering contact is the WhatsApp link above; the number is not shown as text on the page.
- Intro sound: browsers block autoplay audio, so the key clicks play only after the visitor's first tap, click, touch or key press (the speaker button pulses until then); the iOS silent switch also mutes web audio. For troubleshooting, add `?audiodebug` to the URL to log the audio state and every scheduled sound to the console (off by default).
- The FAQ answers on production time ("How long does it take to get my card?") and payment terms ("What are the payment terms?") were supplied by the project owner and should be confirmed with Taply before launch.

## Client onboarding form

A private page where a client enters their details and uploads their logo, profile photo and existing
business card. The brief is emailed to the team. It lives at `/onboard`, is never linked from the public
site, and is kept out of search engines (`noindex,nofollow` meta tag plus an `X-Robots-Tag` header for
`/onboard` and `/api/*` in `vercel.json`). It is loaded as a separate chunk, so the main site's bundle is
unaffected.

### One-time setup

1. **Create a Google App Password** for the Gmail account that will send the briefs:
   turn on 2-Step Verification for that account, then open <https://myaccount.google.com/apppasswords>,
   create an app password (name it "Taply form") and copy the 16-character code.
2. **Create the link secret**: any long random string, for example the output of
   `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`.
3. **Add the variables in Vercel**: Project > Settings > Environment Variables, for Production (and
   Preview if you test there), then redeploy:

   | Name | Value |
   | --- | --- |
   | `FORM_LINK_SECRET` | the random string from step 2 |
   | `NOTIFY_EMAIL` | the address that should receive the briefs |
   | `GMAIL_USER` | the Gmail address that sends them |
   | `GMAIL_APP_PASSWORD` | the app password from step 1 |

   `.env.example` lists the same names. For local work, copy it to `.env.local` (never committed;
   `.env*` is in `.gitignore`). Never put real values in the code or the repository.

### The form link

There is one universal link for every client. With `FORM_LINK_SECRET` and `SITE_URL` in `.env.local`, run:

```bash
npm run link
```

It prints the link (`SITE_URL/onboard?t=<token>`). The token is signed with `FORM_LINK_SECRET` and holds no
client name and no expiry, so the same link can be sent to everyone, again and again, and the command
always prints the same link. Each submission gets its own reference (for example `TP-7K3QXM`), created by
the server when it is sent.

For a one-off link that expires, pass a name and a number of days (default 14):

```bash
npm run link -- "Client or company name" 14
```

Per-client links made before the universal link still work until they expire. A link can't be edited or
guessed. **Changing `FORM_LINK_SECRET` in Vercel invalidates every link, including the universal one**:
run `npm run link` again with the new secret and send the new link out.

### What the client sees

- A missing, edited or expired link shows "This link isn't active." with a WhatsApp button, and no form.
- A valid link shows the form, greeting with "Hi," (no name), on one page: gift toggle, business card
  upload, details, contact and social links, photo, logo and bio, card tagline and notes, then consent.
- A live preview of their card (the same flip card as the "Your card" section) updates as they type.
- Typed text is kept in the browser if they refresh (files are not); it is cleared after sending.
- Images are resized in the browser (1600px max, JPEG about 0.82; logos with transparency stay PNG; SVG and
  PDF are untouched). Everything together must stay under 4 MB.
- After sending: "Thank you, <first name>." (the card owner's, also for gifts), the reference, a draft
  of their card, what happens next, and a WhatsApp button.

### What arrives by email

Subject `New profile details: <full name> (<ref>)`, sent to `NOTIFY_EMAIL` from `GMAIL_USER`, with
Reply-To set to the client's email when they gave one. A short, single-column email (HTML and plain text):
the reference and time in Nairobi, then Person, Contact, Socials, Bio, On the card and Gift order. Only
answered fields are shown; a section with nothing in it is left out. One line names what is attached
(business card, logo, profile photo), and a footer records when consent was given. The files are
attached as `<ref>-logo.png`, `<ref>-photo.jpg`, `<ref>-business-card-1.jpg` and so on. Nothing is
stored on the server.

### Protection

Because the link is shared, the server checks the signed link again, a hidden honeypot field, a minimum
fill time, and a best-effort limit of 5 submissions per connection per hour and 20 per day (over it, the
form says "Too many submissions" with a WhatsApp button). It requires the full name and WhatsApp number,
caps every text field (name and job title 80, company 80, bio 300, tagline 60, notes 1000, links 300),
strips control characters, refuses more than 8 social links, and checks every file by its bytes (PNG,
JPEG, WebP, HEIC, SVG, PDF only; SVGs with scripts or event handlers are refused; at most 5 files and 4 MB
in total). All values are escaped in the email.

If the mail variables are missing on Vercel, the form says "The form isn't set up yet" and offers
WhatsApp, so nobody thinks their details were sent. Locally (`npm run dev`, which serves `/api/*` through
`vite.config.ts`), missing mail variables put the API in DEV MODE: the brief is printed in the terminal, an
HTML preview of the email is written to the system temp folder, and the success screen shows
"DEV MODE: not emailed".
